解析：

A. 内核级线程属于操作系统可直接管理的调度对象，其调度由操作系统内核负责。
B. 操作系统维护的是它能够直接管理的线程实体，即内核级线程；用户级线程通常由线程库在用户空间管理，不要求操作系统为其逐一建立 TCB。
C.用户级线程切换通常在用户态完成，不必每次都陷入内核；内核级线程切换需要操作系统参与，开销一般更大，因此用户级线程切换效率通常更高。
D. 用户级线程本质上可以依赖线程库在用户空间实现，其存在不以前提为“操作系统必须支持内核级线程”。

D. 信号量的 wait() 对应经典的 P 操作。当信号量值不足、资源不可用时，线程无法继续执行，会被阻塞，等待资源可用后再唤醒。因此这类情况是执行态到阻塞态，而不是执行态到就绪态。

复习

进程与线程

概念

程序：静态的，是存放在磁盘里的可执行文件，是一系列的指令集合。
进程：动态的，是程序的一次执行过程。

  • 进程是动态的，进程实体是静态的。
  • 进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。
    资源分配：指一个进程拥有对资源的控制和所有权，包括内存、I/O 通道、I/O 设备。
    调度/执行：指进程是可以被操作系统调度的独立实体。
  • PCB 是进程存在的唯一标志，它常驻内存。
    创建进程，实质上是创建进程映像中的 PCB。
    撤销进程，实质上是撤销/回收进程的 PCB。
    进程执行，系统通过其 PCB 来获取进程的现行状态信息，以便操作系统对其管理/控制。
    进程被创建时，操作系统会为该进程分配一个唯一的 PID。

组成

一个进程实体由 PCB、程序段、数据段组成。

进程控制块 PCB

①进程描述信息：进程标识符 PID、用户标识符 UID、父进程标识符 (PPID)
②进程控制和管理信息：
CPU、磁盘、网络流量使用情况统计、优先级。
进程当前状态：就绪态/阻塞态/运行态。
③资源分配清单：
正在使用哪些文件、正在使用哪些内存区域、正在使用哪些 I/O 设备。
④处理机相关信息：PSW、PC等各种寄存器的值（用于实现进程切换）

程序段

被进程调度程序调度到 CPU 执行的程序代码段。程序可以被多个进程共享。

数据段

一个进程的数据段可以是进程对应的程序加工处理的原始数据，也可以时程序执行时产生的中间或者最终结果。

特征

①动态性（最基本特征）：进程是程序的一次执行过程，是动态地产生、变化和消亡的。具有明确的生命周期，包括创建、就绪、运行、 阻塞和终止等状态变化。与此相对，程序只是一串二进制位，静态存储于硬盘等介质中。
②并发性：内存中有多个进程实体，各进程可并发执行。
③独立性：进程是能独立运行、独立获得资源、独立接受调度的基本单位。
④异步性：各进程按各自独立的、不可预知的速度向前推进，操作系统要提供“进程同步机制”来解决异步问题。
⑤结构性：每个进程都会配置一个 PCB。从结构上看，进程由程序段、数据段、PCB 组成。

PCB

PCB 是进程实体的一部分，记录了用于描述进程的当前情况以及管理进程运行的全部信息。
PCB 的作用是使一个在多道程序环境下不能独立运行的程序成为一个能独立运行的基本单位，一个能与其他进程并发执行的进程。
PCB 主要由以下五个功能：
①作为独立运行基本单位的标志：一个程序配置了 PCB 后，表示它已是一个能在多道程序环境下独立运行的、合法的基本单位，也就具有取得 OS 服务的权利。
②能实现间断性运行方式：在多道程序环境下，进程的运行总是断断续续的。当进程暂停运行时，必须保留 CPU 现场信息，再次被调度时，要恢复其 CPu 现场信息。系统可将 CPU 现场信息保存在被中断进程的 PCB 中，供该进程再次被调度执行时恢复 CPU 现场时使用。
③提供进程管理所需要的信息：当调度程序调度到某进程运行时，根据该进程 PCB 中记录的程序和数据在内存或外存中的始址指针，找到相应的程序和数据；在进程运行过程中，当需要访问文件系统中的文件或 I/O 设备时，也都需要借助 PCB 中的信息。
④提供进程调度所需的信息：只有处于就绪状态的进程才能被调度执行，PCB 中就提供进程处于何种状态的信息。
⑤实现与其他进程的同步与通信：进程同步机制是用于实现诸进程的协调运行的，在 PCB 中还具有用于实现进程通信的区域或通信队队列指针等。

PCB 中的内容

①进程标识符
进程标识符用于唯一地标识一个进程。

外部标识符由创建者提供的，为描述进程的家族关系，应设置父进程标识符和子进程标识符。
还可以设置用户标识，以指示拥有该进程的用户。
内部标识符为方便系统对进程的使用，赋予每个进程一个唯一的数字标识符，通常是进程的序号。

②处理机状态信息
处理机的上下文，主要是由处理机的各种寄存器中的内容组成的。

通用寄存器用户可视寄存器，用户程序可以访问用于暂存信息。
程序计数器 PC存放要访问的下一条指令的地址。
程序状态字 PSW包含状态信息，如条件码、执行方式、中断屏蔽标志等。
用户栈指针指每个用户进程都有一个或若干个与之相关的系统栈，用于存放过程和系统调用参数及调用地址。栈指针指向该栈的栈顶。

③进程调度信息
在操作系统进行调度时，必须了解进程的状态及有关进程调度的信息。

进程调度状态指明当前的进程状态，作为进程调度和上下文切换时的依据
进程调度优先级描述进程优先级的整数，优先级高的进程优先获得处理器
进程调度相关信息它们与所采用的进程调度算法有关

进程与程序关系

进程是动态的，程序是静态的。进程是程序执行的一次运行活动。
进程是暂时的，程序是永久的。进程是一个状态变化的过程，程序可以长久保存。
一个程序可以产生多个不同的进程；一个进程可以执行多个程序。进程可以创建其他进程，而程序不能形成新的程序。
进程具有并发特性，程序没有。

进程和作业的关系

作业是用户需要计算机完成某项任务而要求计算机所作工作的集合。进程是已提交完毕的作业的执行过程，是资源分配的基本单位。
作业时用户向计算机提交任务的任务实体。进程是完成用户任务的执行实体，是向系统申请分配资源的基本单位。
一个作业可由至少一个进程组成，一个进程不能构成多个作业。

进程的状态与转换

进程的五种状态

①运行态（Running）
占有 CPU，并在 CPU 上运行。
在单 CPU 中，任一时刻最多只有一个进程处于运行态，多 CPU 中可能有多个进程处于运行态。
②就绪态（Ready）
具备运行条件，但由于没有空闲 CPU 而暂时不能运行。
系统中可能有多个就绪进程，通常将它们组织成一个队列，称为就绪队列。
③阻塞态（Waiting/Blocked，又称：等待态）
进程因等待某一事件 (如某个资源可用、I/O 操作完成等) 而暂停运行。
系统通常将处于阻塞态的进程组织成一个阻塞队列，甚至根据阻塞原因的不同，还可进一步划分为多个子队列。
④创建态（New）
进程正在被创建，操作系统为进程分配资源、初始化 PCB。
⑤终止态（Terminated）
通过执行 exit 系统调用，请求操作系统终止该进程。
进程正从系统中撤销，操作系统会回收进程拥有的资源、撤销 PCB。

状态间的转换

就绪态→运行态：处于就绪态的进程被调度程序选中，获得 CPU 的使用权, 随即由就绪态转换为运行态。
运行态→就绪态：

  • 处于运行态的进程在时间片用完后，必须主动让出 CPU, 从而转回就绪态；
  • 此外，在可剥夺式调度系统中，若有更高优先级的进程变为就绪，则当前运行的进程也会被强制切换回就绪态，以便让更高优先级的进程执行。

运行态→阻塞态：
当运行中的进程通过系统调用请求某项服务 (如发起 I/O 操作), 而该请求无法立即满足 (需等待 I/O 完成), 进程便会主动进入阻塞态。需注意，并非所有系统调用都会导致阻塞，只有那些需要等待外部事件的操作才会引发状态转换。
阻塞态→就绪态：
当进程所等待的事件发生时 (如 I/O 操作完成), 相应的中断处理程序 会将其状态由阻塞态修改为就绪态，并重新插入就绪队列，等待下一次调度。
不能从阻塞态直接转为运行态，不能从就绪态直接转换为阻塞态。
可以从任何状态直接到终止态。

进程控制

进程控制的主要功能是对系统中所有进程进行有效的管理，主要包括创建新进程、撤销已有进程、实现进程状态转换等操作。
在操作系统中，这些控制操作通常以原语的形式实现。
原语的原子性通过关中断和开中断这两个特权指令对原语的临界区进行保护。
进程控制的实质是让实现进程状态转换及对进程生命周期的管理。

进程的创建

引起进程创建的事件主要有用户登录、作业调度、提供服务、应用请求等。
操作系统通过创建原语建立新进程，具体步骤如下。
①为新进程分配唯一的进程标识号 (PID), 并从系统 PCB 池中申请一个空白 PCB。
②分配新进程运行所需的资源：如内存、文件、I/O 设备等 (记录在 PCB 中)。这些资源或从操作系统获得，或从其父进程继承。
③初始化 PCB: 初始化的内容包括：标识信息、处理机状态信息、调度与控制信息和内存资源信息以及设置进程的优先级。
④插入就绪队列（创建态→就绪态）。
Linux 提供了 fork、vfork和 clone 三种函数用于进程创建。

进程的终止

引起进程终止的事件主要包括：
①正常结束，表示进程完成其预定任务后主动退出。
②异常结束，表示进程在运行过程中发生严重错误，导致无法继续执行。常见原因包括：存储区越界、 非法指令、特权指令违规、算术运算错误、I/O 故障、运行超时等。
③外界干预，由外部实体请求终止进程，如操作员强制终止、操作系统因资源不足或安全策略终止进程、父进程通过系统调用请求终止其子进程。
操作系统通过终止原语（撤销原语）完成进程的撤销，具体步骤如下。
①根据被终止进程的标识符，检索其 PCB, 并读取当前状态。
②若该进程正处于运行态，立即剥夺其 CPU, 并触发调度程序选择下一个就绪进程。
③释放该进程占用的所有系统资源，统一归还给操作系统。
④若系统支持级联终止，则递归终止其所有子孙进程；否则，子孙进程继续运行。
⑤将该进程的 PCB 从所在队列 (或链表) 中移除，完成清理。

进程的阻塞

阻塞原语是主动过程，由进程自己调用阻塞原语来自我阻塞。
条件：
①需要等待系统分配某种资源。
②需要等待相互合作的其他进程完成工作。
③新数据尚未到达、新任务未到达。
阻塞原语的执行过程如下。
①根据进程的 PID ，找到要阻塞进程对应的 PCB。
②保护进程运行现场，将 PCB 状态信息设置为“阻塞态”，暂时停止进程运行。
③将 PCB 插入相应事件的等待队列。
④转到进程调度程序，从就绪队列中选择一个新的进程投入运行。

进程的唤醒

调用唤醒原语不是被阻塞进程本身调用，唤醒对于阻塞进程是一种被动行为。
条件：
①等待的操作/事件已发生。
②等待的数据到达或进程获得了一个新任务。
③进程向系统请求临界资源失败后，使用该临界资源的其他进程释放了资源时。
唤醒原语的执行过程如下。
①在指定事件的等待队列中找到目标进程的 PCB。
②将其从等待队列中移出，并将状态置为就绪态。
③将该 PCB 插入就绪队列，等待调度程序在适当时机选中并恢复其执行。

进程的切换

进程切换一定会涉及中断，通常伴随处理器模式切换，用户态→内核态→用户态。
条件：
①当前进程时间片用完、有更高优先的进程到达。
②当前进程主动阻塞、当前进程终止。
切换原语的执行过程如下.
①保存处理机上下文，包括程序计数器和其他寄存器的内容。
②将运行环境信息存入 PCB，并将该进程的 PCB 移入相应队列。
③选择另一个进程执行，并更新其 PCB 状态。
④根据 PCB 恢复新进程所需的运行环境。

进程间通信

进程通信 (IPC) 是指进程之间的信息交换。根据通信效率和数据量的不同，可分为低级通信和高级通信两类：低级通信主要用于传递控制信息 (如同步、互斥), 典型代表是 PV 操作; 高级通信用于高效传输大量数据，主要包括共享存储、消息传递和管道通信、信号等方式。

共享存储

设置一个可直接访问的共享空间，互斥地访问共享空间，不需要内核介入。

基于数据结构共享
（低级通信）		进程间共享同一个数据结构，适用于传递相对少量的数据。操作系统仅提供共享存储器，由程序员负责对共享数据结构进行设置和对进程间同步进行处理。通信效率低下。限制多，速度慢。
基于存储区共享
（高级通信）		共享内存中的区域，对该共享区读写交换信息。如何共享存储区中数据的形式、数据如何存放等细节问题由进程决定，限制少，速度快。
#### 消息传递 进程间的数据交换以格式化的消息为单位。将通信的数据封装在消息中，进程通过操作系统提供的“发送消息/接收消息”两个原语进行数据交换。 直接通信方式：发送方进程需要指明接收方进程的 ID，消息直接挂到接收进程的消息缓冲队列上。 间接通信方式：通过“信箱”间接通信，指明信箱。发送进程将消息投递到信箱，接收进程从信箱中取出消息。 #### 管道通信 管道实际上是一种固定大小的缓冲区，管道可以实现双向的数据传输，但是无法同时双向传输，只能采用半双工通信，某时间段内只能实现单向的传输，各进程要互斥地访问管道。如果要进行双向数据传输，则需要两个管道。 管道是一个共享文件，不能单纯地从字面上理解为一个传输通道（数据在管道中是先进先出 FIFO 的）。读进程把管道当作输入文件；写进程把管道当作输出文件。 数据以字节流写入管道，当管道写满时，写进程的 write () 系统调用将被阻塞，等待读进程将数据取走。数据被读进程全部取走，管道变空，读进程的 read () 系统调用将被阻塞。 一般允许多个写进程，仅允许一个读进程。 从管道读数据为一次性操作，一旦被读出，就被彻底抛弃消失，读进程最多只有一个。 #### 信号 ### 线程 线程是程序执行流的最小单元，也是处理器调度的基本单位。 线程本身不能单独执行，只能包含在进程中，只能在进程中执行。 #### 线程的主要属性 线程是处理及独立调度和分配的基本单位。 每个线程都有一个线程 ID、线程控制块（TCB）、线程有就绪、阻塞、运行三种基本状态。 线程几乎不拥有系统资源；同一进程的不同线程间共享进程的资源。 同一进程内的所有线程共享该进程的代码段、数据段、堆、文件描述符等系统资源。这种机制使得线程间的通信和数据共享非常高效，无须复杂的进程间通信 (IPC) 机制。 同一进程中的线程切换，不会引起进程切换；不同进程中的线程切换，会涉及进程切换。 切换同进程内的线程，系统开销很小；切换进程，系统开销较大。 内核级线程是处理机调度的基本单位（操作系统能意识到的只有内核级线程）。 #### 线程控制块 TCB 每个线程配置一个线程控制块 TCB，用于记录控制和管理线程的信息。 线程控制块 TCB 通常包括： ①线程标识符 (Thread ID); 类似于 PID。每个线程唯一的标识符 ②寄存器集合，包括程序计数器、状态寄存器和通用寄存器； ③线程当前状态，用于描述线程正处于何种状态； ④调度优先级； ⑤线程局部存储区，用于保存线程私有的数据； ⑥堆栈指针，指向该线程的私有栈，用于过程调用时保存局部变量、返回地址等。 同一进程中的所有线程都完全共享进程的地址空间和全局变量。 同一进程内线程共享的环境：进程代码段、堆、进程的公有数据、进程打开的文件描述符、信号的处理器。 同一进程内线程独立的环境：线程 ID、寄存器组的值、线程的堆栈、错误返回码、线程的信号屏蔽码、线程的优先级。 #### 线程的实现方式 （1）用户级线程 ULT 用户级线程的实现与内核无关。操作系统内核感知不到用户级线程的存在。 线程的管理工作都有用户空间的线程库完成，无需内核帮助。 用户级线程的实现不依赖于操作系统是否支持线程，理论上可以在不支持线程的 OS 上实现。 优点： ①线程切换在用户空间完成，无须切换到内核态，避免了模式切换的开销。 ②调度策略可由应用程序定制，不同进程可根据自身需求采用不同的线程调度算法。 ③用户级线程的实现与操作系统无关，线程管理代码属于用户程序的一部分，具有良好的可移植性。 缺点： ①系统调用的阻塞问题，当某个用户级线程执行一个阻塞型系统调用时，整个进程会被内核挂起，导致进程中的所有线程均被阻塞。 ②无法发挥多处理器的并行优势，由于内核仅将该进程调度到一个 CPU 上执行，即使系统配备了多个 CPU 核心，同一进程中的多个用户级线程也无法同时在不同 CPU 上并行运行，只能在单个 CPU 上交替执行。 （2）内核级线程 KLT 操作系统为每个内核级线程维护一个线程控制块 (TCB)，通过 TCB 堆线程进行管理。 线程是 OS 调度的基本单位，线程的创建和切换由内核完成，需要 CPU 切换到内核态。 优点： ①能发挥多处理器的并行优势，内核可将同一进程中的多个线程同时调度到不同 CPU 核心上并行执行。 ②若进程中的某个线程因系统调用被阻塞，内核仍可调度该进程中的其他线程运行，或切换到其他进程的线程继续执行。 ③内核自身可采用多线程技术，从而提升系统服务的并发性和整体效率。 缺点： 一个用户进程会占用多个内核级线程，线程切换由操作系统内核完成，需要切换到内核态，每次切换都有模式转换开销，因此线程管理的成本相对较高，开销大。 #### 多线程模型 （1）一对一模型 将每个用户级线程映射到一个独立的内核级线程，所示。进程中的用户级线程与内核级线程一一对应，线程的调度由内核完成，需要切换到内核态。 优点： 一个线程被阻塞后，其他线程可以继续执行，有较强的并发能力。 多线程可以在多核处理机上并行执行。 缺点： 每创建一个用户线程，系统就必须创建一个对应的内核线程，系统切换有操作系统内核完成，需要切换到核心态，导致较大的系统开销。 （2）多对一模型 将多个用户级线程映射到一个内核级线程，每个进程仅拥有一个内核级线程。 优点：用户级线程切换在用户空间进行，不需要切换到内核态，线程管理系统开销小、效率高。 缺点： 当一个用户级线程被阻塞时，内核并不知晓哪个进程被阻塞，导致整个进程被阻塞，降低了并发性。多个线程不能再多核处理机上并行运行。 操作系统只“看得见”内核级线程，只有内核级线程才是处理机分配的单位。 （3）多对多模型 将 n 个用户级线程映射到 m 个内核级线程，要求 n≥m。每个用户进程对应 m 个内核级线程。 优点： 既克服了多对一模型并发度低的缺陷，又避免了一对一模型资源开销过大的问题。 用户级线程切换高效，且支持多核并行与阻塞隔离。 用户级线程承担“代码逻辑”的执行，而内核级线程则承担“运行机会的分配”。 #### 线程的控制

调度

调度层次

（1）高级调度（作业调度）
作业调度实现了内存与外存之间的调度。频率最低。
根据特定规则，从外存的作业后备队列中选出一个作业并加载到内存中，创建进程。每个作业只调入一次，调出一次。作业调入时会创建其 PCB，而调出时则会销毁其 PCB。
作业调度每次要接纳多少个作业进入内存取决于多道程序的并发程度，即允许有多少个作业同时在内存中运行。
无→创建态→就绪态。
（2）中级调度（内存调度）
引入其的主要目的是提高内存利用率和系统吞吐量。
根据某种策略决定将哪个处于挂起状态的进程重新调入内存。
当内存不足时，可以将暂时不能运行的进程数据调出到外存。内存空闲或进程需要运行时，再将数据重新加载回内存。中级调度实际上就是存储器管理中的对换功能。
处于外存等待的进程会进入挂起状态，并被组成挂起队列。只有在进程终止时，进程的 PCB 才会被撤销 。
挂起态↔就绪态。
（3）低级调度（进程调度/处理机调度）
按照某种策略从就绪队列中选取一个进程，将处理机（CPU）分配给它。
进程调度是操作系统中最基本的一种调度，操作系统中都必须配置具备进程调度功能。
需要区分“进程调度”与“上下文切换”的不同。调度是一种资源分配的行为，包括了调度程序的决策以及上下文切换，如果调度程序决定切换任务，则会调用上下文切换函数。
就绪态→运行态。

  1. 作业调度为进程活动做准备，将作业调入内存并创建进程，使其具备参与调度的资格。
  2. 中级调度起调节作用，通过将暂时无法运行的进程换出至外存 (挂起态), 或在条件满足时将其重新换入内存 (恢复为就绪态), 动态调整内存中活跃进程的数量。
  3. 进程调度驱动实际执行，从就绪队列中选择进程投入运行，是实现并发的核心机制。
  4. 调度频率依次升高：作业调度频率最低，中级调度次之，进程调度频率最高。

进程调度的任务

①保存 CPU 现场信息。
②选取待运行进程。
③完成 CPU 分配

调度程序

调度程序通常由三部分组成：
①排队器。按照特定调度策略，系统将所有就绪进程按顺序排成一个或多个队列。每当有进程变为就绪状态时，排队器会将其插入相应的就绪队列。
②分派器。调度算法选定进程后，从就绪队列中提取该进程并将 CPU 分配给它。
③上下文切换器。在切换处理器时，涉及两次上下文切换操作：第一步，将当前进程的上下文保存到其 PCB 中，再装入分派程序的上下文以便执行；第二步，移出分派程序的上下文，并将新选进程的 CPU 状态信息装入到处理器的各个寄存器中。

调度的时机

通常在以下情况下需要进行进程调度与切换：

  • 创建新进程后，父进程和子进程都处于就绪态，因此需要决定是运行父进程还是子进程，调度程序可以合法地选择其中一个先运行。
  • 进程正常结束或异常终止后，必须从就绪队列中选择某个进程运行；若没有就绪进程，则通常运行一个系统提供的闲逛进程。
  • 当进程因 I/O 请求、信号量操作或其他原因而被阻塞时，必须调度其他进程运行。
  • 若更高优先级的进程进入就绪队列，或当前进程的时间片用完，也会触发调度并可能剥夺当前进程的 CPU。
    在以下情况下不能进行进程调度与切换：
  • 处理中断的过程中。中断处理逻辑复杂，实现上难以安全地进行进程切换；同时，中断处理属于系统内核工作，逻辑上不隶属于任何用户进程，不应被剥夺 CPU 资源。
  • 执行原子操作的过程中。
  • 进程在操作系统内核程序临界区中。

调度的方式

（1）非剥夺调度方式（非抢占式）
进程只能主动放弃处理机。在运行过程中如果有其他更紧急的任务到达，当前进程仍会继续占用处理机，直到其完成或主动进入阻塞态。处理机才会分配给其他进程。
调度发生的时机：进程运行完毕；进程发生某种事件而无法继续运行；进程发生阻塞需要等待继续运行的条件。
实现简单，系统开销小，但是无法及时相应紧急任务，适合于早期批处理系统，不能用于分时系统和大多数实时系统。
（2）剥夺调度方式（抢占式）
当一个进程正在使用处理机时，如果有更重要或更紧急的进程需要 CPU 则会立即中断当前进程，暂停其执行，并将处理机分配给更紧急的进程。
优先处理更紧急的进程，允许各进程轮流按时间片执行（通过时钟中断机制）。适用分时操作系统、实时操作系统。
抢占遵循常用原则：优先级高低；短进程优先；时间片轮转原则。

闲逛进程

进程切换时，若系统中没有就绪进程，就会调度闲逛进程运行，如果没有其他进程就绪，该进程就一直运行，并在执行过程中检查中断是否发生。
闲逛进程的优先级最低，只要有进程进入就绪状态，就会立即让出处理机。
闲逛进程不需要 CPU 之外的资源，通常情况它不会被阻塞。

两种线程的调度

①用户级线程调度。内核并不直接管理线程，而是由进程中的调度程序控制哪些线程运行。内核仅选择一个进程并给予时间片，线程的调度完全依赖进程内部的调度程序。
②内核级线程调度。内核直接选择并调度线程，而不关心该线程属于哪个进程。线程将被分配一个时间片，超出时间片后会强制剥夺 CPU 并转为就绪态。
用户级线程的切换只在同一进程内进行，所需的机器指令较少；内核级线程的切换需要保存和恢复线程上下文，与用户级线程相比，其开销相对较大，可能导致一定的延迟。

调度的目标

CPU 利用率利用率=忙碌时间/总时间
系统吞吐量单位时间 CPU 完成作业的数量
系统吞吐量=总共完成作业数/总共花的时间
周转时间指从作业被提交给系统开始，到作业完成为止的这段时间间隔。
周转时间=作业完成时间-作业提交时间

四部分：


①作业在外存后备队列上等待作业调度的时间
②进程在就绪队列上等待进程调度的时间
③进程在 CPU 上执行的时间
④进程等待 I/O 操作完成的时间
平均周转时间平均周转时间=各作业周转时间之和/作业数
带权周转时间带权周转时间=作业周转时间/作业实际运行时间
平均带权周转时间平均带权周转时间=各作业带权周转时间之和/作业数
等待时间指进程/作业处于等待处理机状态时间之和。
对于进程来说，等待时间就是指进程建立后等待被调度执行的时间之和，进程在等待 I/O 完成时不算做等待时间，因为该期间进程仍然处于阻塞状态。
对于作业来说，等待时间除了包括进程创建后的等待时间，还应包括作业在外存后备队列的等待时长。
调度算法只会影响作业/进程的等待时间。
平均等待时间即各个进程/作业等待时间的平均值。
响应时间指用户首次提交请求到首次产生响应所用的时间。
### 调度算法 #### 先来先服务（FCFS）
算法规则按照作业/进程到达的先后顺序来分配处理器
调度策略用于作业调度时，考虑的是哪个作业先到达后备队列，并依次调入内存执行。
用于进程调度时，考虑的是哪个进程先到达就绪队列，并依次转为执行态并为其分配处理器资源。
抢占性非抢占式、不可剥夺算法
优点公平、算法实现简单
缺点排在长作业（进程）后面的短作业需要等待很长时间，带权周转时间很大。
FCFS 算法对长作业有利，对短作业不利，长作业排队并使用处理器直到完成，相对短作业使用处理器的时间更长。
FCFS 有利于 CPU 繁忙型作业，不利于 I/O 繁忙型作业。I/O 繁忙型进程遇到 I/O 操作会陷入阻塞而重新排队，CPU 繁忙型进程相对排队次数少。
#### 最短作业优先（SJF）
思想每次调度选择剩余处理器使用时间最短的进程。追求最少的平均等待时间，最少的平均周转时间，最少平均带权周转时间。
算法规则最短的作业/进程优先得到服务
每次调度时选择当前已到达且运行时间最短的作业/进程。
调度策略既可以用于作业调度，也可以用于进程调度。
用于进程调度时称为“短进程优先”算法。
缺点对短作业有利，长作业不利。可能产生饥饿现象。
必须预知作业的运行时间，人机无法实现交互。
完全未考虑作业的紧迫程度，不能保证紧迫性作业会被及时处理。

最短剩余时间优先算法（SRTF）

本质SJF 的抢占版本
思想每当有进程加入就绪队列改变时就需要调度，如果新到达的进程剩余时间比当前运行的进程剩余时间更短，则由新进程抢占处理机，当前运行进程重新回到就绪队列。另外当一个进程完成时也需要调度。
细节如果未特别说明，短作业/进程优先算法默认是非抢占式的。
抢占式的短作业/进程优先调度算法的平均等待时间、平均周转时间最少。
#### 时间片轮转调度算法（RR）
算法规则按照进程到达就绪队列的顺序，轮流分配时间片。若进程在一个时间片内未执行完，则会被剥夺处理机，并将该进程放回就绪队列的尾部等待下一次调度。
调度策略用于进程调度
调度时机一个时间片耗尽，在时钟中断发生时，调度程序调度下一个就绪进程到处理器上运行，将当前进程重新放回到就绪队列尾部。
一个时间片未耗尽，但进程已完成工作，或因阻塞等原因放弃处理器资源，调度程序会选择下一个就绪程序进行调度。
抢占性若进程未能在时间片内执行完，将会被强行剥夺处理机使用权，抢占式。
由时钟装置发出时钟中断来通知 CPU 时间片已到。
优点公平；响应快；不会饥饿，适用于分时操作系统。
缺点频繁的进程切换会导致一定的开销，并且该方法不区分任务的紧急程度。
时间片大小影响若时间片太大，使每个进程都在一个时间片内完成，则算法退化为 FCFS，并且会增大进程响应时间。
若时间片很小，处理机将在进程间频繁地切换，使处理机开销增大，而真正用于运行用户进程的时间将减少。
#### 优先级调度算法
算法规则调度时选择优先级最高的作业/进程
调度策略既可以用于作业调度，也可以用于进程调度。
抢占性抢占式、非抢占式都有。区别：非抢占式调度仅在进程主动放弃 CPU 时进行调度，而抢占式调度则需要检查就绪队列是否有更紧急的进程需要抢占 CPU。
优点用优先级区分紧急进程、重要程度，适用于实时操作系统，可灵活的调整对各种作业/进程的偏好程度。
缺点如果高优先级进程持续到来，可能会导致低优先级进程发生饥饿现象。
补充①优先级可分为静态优先级和动态优先级。
②系统进程优先级高于用户进程；前台进程优先级高于后台进程。
③操作系统更偏好 I/O 型进程（I/O 繁忙型进程）。
④对资源要求少的进程优先级高于对资源要求多的进程。
动态优先级调整①如果进程在就绪队列中等待了很长时间，则可以适当提升优先级。
②如果进程占用处理机运行了很长时间，则可以适当降低优先级。
③如果发现进程频繁进行 I/O 操作，则可以适当提升优先级。

最高响应比优先调度算法（HRRN）

思想综合考虑作业/进程的等待时间和要求服务的时间。
算法规则每次调度时先计算各个作业/进程的响应比，选择响应比最高的作业/进程为其服务。
响应比=（等待时间+要求服务时间）/要求服务时间
调度策略既可用于作业调度，也可用于进程调度。
抢占性非抢占式。仅当前运行的作业/进程主动放弃处理机时，才需调度，才需计算响应比。
优点该算法综合考虑了等待时间与服务时间。在等待时间相同的情况下，优先选择服务时间较短的作业；而服务时间相等时，则优先选择等待时间较长的作业。
对于长作业，随着等待时间的增加，其响应比逐渐增大，有效避免长作业节现象的发生。
是否饥饿不会导致饥饿
#### 多级反馈队列调度算法
思想对其他调度算法的折中权衡
算法规则采用多级就绪队列结构，各队列按优先级从高到低排序，并设定不同的时间片长度，从小到大递增。
当新进程到达时，首先进入第 1 级队列，并按照 FCFS 原则排队等待分配时间片。如果进程用完时间片但未完成，将被转移至下一级队列的队尾。如果该进程已经在最底层队列，仍会重新放回最底层队尾。
只有当第 k 级队列为空时，才会为第 k+1 级队列中的进程分配时间片。
抢占式在 k 级队列的进程运行过程中，如果更高优先级队列中有新进程到达，由于优先级更高，这个新进程会抢占当前进程的处理机，原进程会被放回第 k 级队列的队尾。
优点①对各类型进程相对公平（类似 FCFS 的优点）
②每个新到达的进程可以迅速得到响应（类似 RR 的优点）
③短进程可以快速完成（类似 SPF 的优点）
④不需要提前估计进程的运行时间
⑤可灵活调整对不同类型进程的偏好，如 CPU 密集型、I/O 密集型进程（I/O 阻塞的进程可被重新放回高优先级队列，I/O 型进程保持较高优先级）
缺点会饥饿：如果高优先级队列总是有新任务进入，而低优先级队列中的任务无法提升到更高的优先级，低优先级任务可能会一直处于饥饿状态。

多处理机调度

需要考虑的两个目标：
（1）负载均衡
尽可能让每个 CPU 都同等忙碌。
实现方法：

  • 推迁移：定期检查每个处理器的负载，若发现不平衡，会将进程从过载处理器推送到空闲或较少负载的处理器。
  • 拉迁移：空处理器主动从繁忙处理器上拉取等待中的进程。
    （2）处理器亲和性
    尽量让进程调度到同一个 CPU 上运行，以发挥 CPU 中缓存的作用。
