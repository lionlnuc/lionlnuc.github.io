答案：

D

解析：

与宏内核相比，微内核通常具有较高的可靠性、较高的安全性、较强的可扩展性，但不具有较好的性能。

判断这题的关键，是先抓住微内核的基本设计思想：

  • 微内核只把最基本、最核心的功能保留在内核中；

  • 操作系统的大部分其他功能，如部分服务、驱动等，放到用户态作为独立进程运行；

  • 这些用户态服务之间、以及它们与内核之间，往往需要通过 IPC（Inter-Process Communication，进程间通信） 来协作。

  • 不要把“结构先进”误等同于“性能更好”。微内核的优势主要在可靠性、安全性、可扩展性，不在运行效率。

  • 题干比较对象是**“与宏内核相比”，因此要按两者典型差异作答，而不是只看“性能”这个词的宽泛含义。

  • 记忆时可抓一句话：微内核优点在“稳、安、易扩展”，缺点在“通信开销大、性能偏低”。

答案：

查看答案

B

解析：

中断现场保存完整分类（硬件自动保存 + OS软件保存）

一、硬件自动保存（CPU硬件电路完成，无需操作系统干预）
发生中断瞬间，硬件自动压入栈：
1. PC程序计数器：被中断指令的下一条指令地址，中断返回后从此处继续执行（对应题目A选项）
2. PSW程序状态字：标志位（溢出、正负、中断屏蔽位、特权级等），记录中断前CPU运行状态
二、操作系统（中断服务程序）手动保存（软件操作，题目考点）
进入内核中断处理函数后，操作系统主动把通用寄存器全部压栈保存（对应题目B选项）：

  • 通用数据寄存器（AX/BX/CX/DX等）
  • 基址、变址寄存器（BP、SI、DI等）
    中断处理完成后，再按顺序弹出恢复，保证原进程运算数据不丢失。
    三、不需要保存的两类高速缓存（TLB、Cache，题目C、D）
    1. TLB快表：页表高速缓存，仅缓存虚拟-物理地址映射，丢失无影响，缺页时重新查询页表即可，中断无需保存
    2. Cache高速缓存：CPU与内存间缓存，数据副本同时存在内存，中断不用保存；Cache失效只会轻微影响速度，不会破坏进程上下文
    速记区分
  • 硬件存：PC、PSW
  • OS存：所有通用寄存器
  • 不存：TLB、Cache、内存数据

操作系统的概念

概念

  • 操作系统是一组能有效地组织和管理计算机硬件和软件资源、合理地对各类作业进行调度、以及方便用户使用的程序的集合。
  • 操作系统是硬件上的第一层软件，是最基本的系统软件，最接近硬件的软件。
  • 操作系统提供给用户和其他软件方便的接口和环境（向上层提供服务，上层即用户和软件；操作系统屏蔽底层硬件细节，使用户在使用时无需关心底层如何实现功能——即封装思想）。

功能和目标

1.操作系统作为计算机系统资源的管理者

处理机管理 在多道程序环境下，处理机的分配和运行都以进程 (或线程) 为基本单位，因此处理机管理本质上是对进程的管理。
进程管理的主要任务包括进程控制、进程同步、进程通信、死锁处理以及处理机调度等。
存储器管理 为多道程序提供良好的内存运行环境，方便用户使用并提高内存利用率。
主要功能包括内存分配与回收、地址映射、内存保护与共享，以及内存扩充等。
文件管理 文件存储空间的管理、目录管理、文件读/写操作及访问保护等。
设备管理 处理用户的 I/O 请求，屏蔽设备差异，方便用户使用各类外设，并提高设备利用率。
主要包括缓冲管理、设备分配、设备驱动处理和虚拟设备等功能。
处理机管理

进程控制：操作系统需要为每道作业创建进程，撤销/终止已结束的进程、控制进程在运行过程中的状态切换。
进程同步：对多个进程（含线程）的运行进行协调。
进程通信：实现相互合作进程之间的信息交换。
进程调度：按照一定的算法把处理器分配给进程。

存储器管理

内存分配：

  • 通过一定的分配策略为每道程序分配内存空间。
  • 提高存储器的利用率，尽量减少不可用的内存空间。
  • 允许正在运行的程序申请附加内存空间，以适应程序和数据的动态增长。

两种分配方式：

  • 静态分配：作业所需的内存空间装载时确定，整个运行期间不允许该作业再申请新的内存空间。
  • 动态分配：允许在运行过程中动态申请新的内存空间，以适应程序和数据的增长。

内存保护：保证各程序在各自的空间运行而互不干扰，不允许用户程序访问操作系统和其他用户的程序和数据。

地址映射：将地址空间中的逻辑地址转换为内存空间中与之对应的物理地址。

内存扩充：从逻辑上扩充内存容量，使用户感觉到的内存容量比实际内存容量大得多。以便让更多的用户程序能并发运行。

文件管理

文件存储空间的管理：由文件系统对诸多文件及其所占据的存储空间实施统一的管理。

  • 为文件分配必要的外存空间，提高外存利用率，提高文件系统的存取速度。
  • 设置相应的数据结构，用于记录文件存储空间的使用情况，以供分配存储空间时参考，并具有对存储空间进行分配和回收的功能。

目录管理：

  • 为每个文件建立一个目录项，目录项包括文件名、文件属性、文件在磁盘上的物理位置等，并对众多的目录项加以有效的组织，以实现方便的按名存取。
  • 实现文件共享，只需在外存中保留一份该共享文件的副本即可。
  • 提供快速的目录查询手段，以提高对文件检索的速度。

文件的读/写管理：根据用户的请求，从外存中读取数据，或将数据写入外存。
文件保护：防止系统中的文件被非法窃取和破坏，提供有效的存取控制功能。防止未经授权的用户对文件的操作和访问。

设备管理

设备管理的基本任务是完成用户进程提出的 I/O 请求，分配所需的 I/O 设备，完成指定的 I/O 操作。提高 CPU 和 I/O 设备的利用率和并行程度，提高 I/O 速度。
缓冲管理：通过在 I/O 设备和 CPU 之间引入缓冲，可以解决速度不匹配的矛盾，提高 CPU 利用率，提高系统吞吐量。
设备分配：对于用户进程的 I/O 请求，根据系统现有的资源情况，按照某种设备分配策略为其分配所需的设备。
设备处理：设备处理程序即设备驱动程序，主要用于实现处理器和设备控制器之间的通信。
虚拟设备：操作系统的虚拟性。

2.操作系统作为用户与计算机硬件系统之间的接口
（1）用户接口

| 联机用户接口
（交互式命令接口） | 用户输入命令后，系统立即解释并执行，完成后返回控制权，适用于实时交互场景。
“雇主”说一句话，“工人”做一件事，并做出反馈，强调交互性。 |
| 脱机用户接口
（批处理命令接口） | 用于批处理系统。
“雇主”预先将任务清单交给“工人”,“工人”按清单逐条完成这些任务。 |
| 图形用户接口
（GUI） | 提升易用性，通过图标、菜单、对话框等图形元素替代文本命令。
用户借助鼠标等设备进行操作，底层通过系统调用与内核交互，显著降低了使用门槛。 |

（2）程序接口
程序接口是应用程序在运行时请求操作系统服务、访问系统资源的唯一合法途径，其核心是一组系统调用。每个系统调用对应内核中实现某个特定功能的子程序。当应用程序需要操作系统服务时，必须通过调用相应的系统调用来完成。
注意，库函数本身并非操作系统接口，它们只是对系统调用的封装。

操作系统的四个特征

并发——最基本的特征

并发：指两个或多个事件在同一时间间隔内发生。在单处理器系统中，宏观来看，这些程序是同时向前推进的；而微观来看，并发执行的程序是交替在处理器上执行的。
并行：指两个或多个事件在同一时刻同时在不同的处理单元上运行。并行通常需要多处理器等硬件支持。并行是并发的特例，程序并行性一定是并发的，反之则不一定成立。

共享——最基本的特征

共享是指系统中的资源可供内存中多个并发执行的进程共同使用。
两种资源共享方式：
根据资源特性与访问方式 的不同，共享主要分为互斥共享和同时访问两种形式。

互斥共享方式 要求一个资源在一段时间内只满足一个请求，只能供一个作业使用。
一个时间段内只允许一个进程访问该资源，释放该资源后才允许另一个进程对该资源进行访问。（临界资源）
计算机系统中的大多数独占型物理设备 (如打印机), 以及软件中的栈、变量、表格等，均属于临界资源，必须以互斥方式共享。
同时访问方式 此处的“同时”通常指逻 辑上的并发访问，微观上这些进程可能通过分时交替方式访问资源，即分时共享。
允许一个时间段内有多个进程“同时”对他们进行访问（宏观同时、微观交替）

并发和共享二者互为前提：
①资源共享以进程的并发执行为前提，若系统仅支持单道程序，则无须考虑资源共享；
②有效的资源共享机制是并发执行的基础，若无法协调资源访问，则并发程序将因竞争冲突而无法正确运行。

虚拟

虚拟是指通过某种技术手段，将一个物理实体映射为多个逻辑上的对应物。物理实体是实际存在的，而逻辑上的对应物是用户感受到的。
操作系统主要通过两类复用技术实现虚拟：时分复用和空分复用。

时分复用技术 通过利用处理机空闲时间运行其他程序，提高利用率。
虚拟处理器：处理器被多个程序“时分”地使用，微观上交替执行。
虚拟设备技术：利用时分复用技术，将物理上的 I/O 设备虚拟为多台逻辑上的 I/O 设备。
空分复用技术 利用存储器的空闲区域存放和运行其他的多道程序。
单纯采用空分复用技术的存储器只能提高内存利用率，并不能实现在逻辑上扩大内存容量的功能，还应引入虚拟存储技术。
虚拟存储器技术：将一台机器的物理存储器变为虚拟存储器，将内存划分给多个程序使用。其本质上是实现内存的分时复用。
异步

在多道程序环境下，多个进程并发执行。但由于系统资源有限，进程的执行并非连续进行， 而是以不可预知的速度断续推进，这种特性称为进程的异步性。
可能导致与时间相关的错误。
拥有并发性才有可能导致异步性。

操作系统的发展

手工操作阶段

人工操作阶段

用户将准备好的穿孔纸带或卡片放入输入输出设备，计算机读取其中的程序和数据并运行。只有当前程序运行完毕并取出结果后，下一个用户才能使用计算机。
手工操作阶段存在两个突出缺点：①用户独占全机，虽无资源竞争，但系统资源利用率极低；②CPU 长时间空闲，等待人工完成 I/O 操作，导致其计算能力未能充分发挥。

脱机 I/O 方式

引入一台外围机，在 CPU 不参与的情况下，预先完成 I/O 准备工作：输入时，外围机将纸带或卡片上的程序和数据读入磁带，供 CPU 后续调入内存；输出时，CPU 将结果先写入磁带，再由外围机将磁带内容输出至外设。
脱机 I/O 的主要优点包括：①装带、卸带及数据传输等操作在脱机状态下由外围机完成，显著减少了 CPU 空闲时间；② CPU 可直接从高速磁带读取或写入数据，大幅提升了 I/O 效率。

批处理阶段

单道批处理系统

引入脱机输入/输出技术，并用监督程序负责控制作业的输入输出。
主要特征：

  • 自动性：磁带上的作业可自动连续执行，无须人工干预。
  • 顺序性：作业按磁带上的顺序依次装入内存，先装入者先完成。
  • 单道性：内存中仅允许一道用户程序运行；监督程序每次仅从磁带调入一道作业，待其完成或异常终止后才装入下一道。
    优点：缓解人机速度矛盾，减少 CPU 空闲时间；提高了I/O 速度，提升资源利用率。
    缺点：内存中同一时刻只能有一道程序运行，且它在执行时独占资源，并在 CPU 上连续执行。但 CPU 在等待 I/O 完成期间无法处理其他任务，导致大量时间处于空闲，整体 CPU 利用率较低。
多道批处理系统

用户提交的作业首先存放在外存的后备队列中。作业调度程序按一定算法从该队列中选取若 干作业调入主存，并且允许多个作业并发运行，这些作业共享处理器、外设以及其他资源。
主要特征：

  • 制约性：程序执行因为共享资源及相互协同的原因产生了竞争，相互制约。
  • 间断性：考虑竞争的公平性，程序的执行是断续的。
  • 共享性：内存中的多个程序共享系统中的各种软硬件资源。

优点：

  • 多道程序并发执行，资源利用率大幅提升。
  • 系统吞吐量大。
  • 宏观上并发。
  • 微观上串行。

缺点：

  • 无交互能力。
  • 平均周转时间长。
    多道程序环境需要付出额外的开销（作业调度开销、上下文切换开销、内存管理开销、资源竞争开销、进程间通信和同步开销）来组织作业和切换作业，管理内存以及处理各种任务。

分时操作系统

分时技术是指将处理器时间划分为很短的时间片，轮流分配给各用户程序使用。用户可与计算机进行交互。
特点：
同时性：多路性，允许多个终端用户同时使用一台计算机，并按分时原则为每个用户服务。
交互性：即用户通过终端采用人机对话的方式直接控制程序运行。
独立性：多个用户可以彼此独立地进行操作，互不干扰，单个用户感觉不到别人也在使用这台计算机。
及时性：用户地请求能在短时间内获得响应。
优点：及时接收，及时处理。
缺点：对每个用户/作业完全公平，循环地为每个用户/作业服务一个时间片，不区分任务的紧急性，不能优先处理紧急任务。

实时操作系统

计算机系统在接收到外部信号后及时处理，并且要在严格的时限内处理完事件。
主要特点是及时性和可靠性。其进程调度采用抢占式的优先级调度算法。
优点：能够响应并优先处理紧急任务，某些紧急任务无需等待时间片排队。
硬实时操作系统：必须在绝对严格的规定时限内完成处理。
软实时操作系统：能接受偶尔违反时间限制。

网络操作系统

网络操作系统是在单机操作系统基础上扩展网络功能而形成的系统，主要用于支持计算机之间的通信、数据传输以及资源共享 (如文件、打印机共享等)。

分布式操作系统

用于管理分布式计算机系统的操作系统称为分布式操作系统，
特征：节点地位对等，无固定的主从关系； 系统资源可被所有用户透明地共享；具备良好的可扩展性与容错能力，支持动态重组；能够将一个任务分解为多个子任务，并分布到不同节点上并行执行、协同完成。
特点：分布性、并行性、统一性、自治性、共享性和透明性。

程序运行环境

两种程序

内核程序：可以执行一些特权指令
应用程序：只能执行非特权指令

两种指令

特权指令 非特权指令
不允许用户直接使用的指令（内核态下运行） 允许用户直接使用的指令（用户态下运行）
有关 I/O 的指令；访问程序状态字寄存器的指令；设置系统时钟时间；关中断；存取特殊寄存器（如用于内存保护的寄存器）的指令；其他访问系统状态和直接访问系统资源的指令等。切换到用户态的指令也是特权指令。 不能直接访问系统中的软硬件资源；
只限于访问用户的地址空间。
对于内存空间的访问范围基本不受限制 应用程序所使用的都是非特权指令。
如：内存清零指令，指令影响重大，只允许管理者（操作系统内核）使用 如：加法指令、减法指令、访管指令
这种限制由硬件强制执行，若应用程序尝试执行特权指令，硬件会将其判定为非法操作并拒绝执行，同时发出权限错误信号。操作系统捕获此信号后，会立即转入相应的错误处理程序，中止该应用程序的运行，并重新进行调度。

两种处理器状态

用于区分正在运行的是内核程序或应用程序，主要区别：能否访问硬件。

内核态（核心态、管态） 用户态（普通态、目态）
运行内核程序，可以执行特权指令。 运行应用程序，只能执行非特权指令。
在用户态下，进程只能访问自己的地址空间，不能直接调用内核函数。
用户态转为内核态唯一的途径是中断或异常。

区分两种状态

CPU 中的 PSW 寄存器（程序状态字寄存器），其中有个二进制位（模式位），通常情况下用 0/1 表示内核态（0）或用户态（1）。

状态切换

  1. 内核态→用户态
    执行特权指令，修改 PSW 标志位为用户态，操作系统主动让出 CPU 控制权。
  2. 用户态→内核态
    由中断引发，该状态转换过程由 CPU 硬件自动完成。
    计算机通过硬件完成操作系统由用户态到内核态的转换。当发生中断事件时，硬件检测到这一动作后，自动将 CPU 状态置为核心态。
  3. 访管指令（Trap 指令/陷入指令）
    由用户态转到内核态，则会用到访管指令，访管指令（Trap 指令）是在用户态使用的，用于引发访管中断，请求进入内核态。

访管中断：因请求操作系统服务而自愿中断，转为内核态，由访管指令（陷入指令）产生。
访管指令本身是非特权指令，但它触发的中断处理程序是在内核态执行的。

两种状态的事件/指令

用户态 事件 系统调用、外部中断、缺页
指令 陷入指令（Trap）跳转指令、数据传送指令、设置断点
内核态 事件 进程切换、缺页处理
指令 关中断、I/O 指令、所有特权指令

内核的三大基本支撑功能

时钟管理
  • 计时功能，操作系统需要通过时钟管理向用户提供标准的系统时间。
  • 通过时钟中断的管理，可以实现进程的切换。
  • 每当定时器出发时钟中断，时钟中断处理程序更新的内容：a.内核中时钟变量的值（整个系统用了多少时间）；b.当前进程已使用的 CPU 时长；c.进程在当前时间片内剩余的执行时间。
  • 获取（读）时钟可以在用户态进行，但设置（写）时钟必须在内核态进行。
中断机制
  • 目的：提高多道运行环境中 CPU 的利用率，它允许 CPU 在 I/O 操作期间执行其他指令。
  • 中断来源广泛，包括键盘输入、鼠标事件、进程的管理和调度、系统调用、设备驱动和文件访问等。中断是现代操作系统运行的基础。
原语

它是一组由若干条指令组成、用于完成特定功能的过程。
原子性：原语是原子操作。这意味着它的所有动作要么全部完成，要么全部不执行，是一个不可分割的基本单位。由于其原子性，原语在执行过程中不允许被中断。
原语在内核态下执行，并且常驻内存。常用于实现对关键数据结构的原子操作或同步机制。

中断和异常

中断的作用
  • 中断会使 CPU 由用户态变为内核态，OS 重新夺回对 CPU 的控制权。（硬件实现）
    硬件实现：用一个特殊寄存器来表示 CPU 当前的工作状态是内核态还是用户态。
  • 如果没有中断机制，就无法高效的进行并发。
  • 中断是操作系统内核夺回 CPU 使用权的唯一途径（用户态→内核态）。
中断的类型

①内中断（异常、例外）
与当前执行的指令有关，中断信号来源于 CPU 内部，由某个指令引发的中断。检测异常的工作由 CPU（包括控制器和运算器）实现的。内中断通常不能被屏蔽，一旦出现应立即处理。

类型 概念 例子
陷入（trap） 由陷入指令引发的，应用程序故意引发。 系统调用（陷入指令并非特权指令，且需要在用户态下执行，系统调用通过陷入指令完成）。
故障（fault） 由错误条件引起，可能被内核程序修复，CPU 使用权交还应用程序。若不能被修复，则终止程序 缺页故障、运算溢出等。
终止（abort） 由致命错误引起，内核程序无法修复该错误，并且不会交还 CPU 使用权，而是直接终止应用程序。 除法指令除数为 0，非法使用特权指令
常见的内中断：地址非法、数据校验错误、访存缺页、存储访问控制错、算数操作上溢、数据格式非法、除数为 0、非法指令、用户程序执行特权指令、陷入指令、运行超时、等待超时、算数运算错。
内中断一旦出现立即处理，返回的地方可能是发生异常的指令，也可能直接跳过。
②外中断（也称硬件中断）
与当前执行的指令无关，中断信号来源于 CPU 外部。
时钟中断：时钟部件发出的中断信号，该部件每隔一个时间片，给 CPU 发送一个时钟中断信号。
时钟中断的主要工作：处理和时间有关的信息以及决定是否执行调度程序。包括系统时间、进程的时间片、延时、使用 CPU 的时间、各种定时器、进程已执行的时间、进程在时间片内的剩余执行时间等。
I/O 中断：由输入输设备发出的中断信号。
常见的外中断：程序 I/O 中断、DMA 中断、通道中断、时钟中断。
内中断（异常）会引起中断，但中断未必是内中断引起的（也可由外中断）。
软件中断：在程序中使用软件中断指令使机器进入中断处理的过程，不是随机产生的。
硬件中断：由随机产生的硬件事件产生的中断。
类型 原因 同/异步 中断来源 返回
中断 I/O 设备的请求信号 异步 外部设备 返回下一条指令
故障 可能恢复的异常事件 同步 访存、除法指令 可能返回当前指令
陷阱 故意安排的异常事件 同步 陷入指令 返回下一条指令
终止 无法恢复的异常事件 同步 硬件损坏 不返回

中断机制的基本原理

内中断：CPU 在执行指令时会检查是否有异常发生。
外中断：每个指令周期末尾，CPU 会检查是否有外部中断信号需要处理。
中断向量表：CPU 检测到中断后，根据中断信号的类型去查询中断向量表，找到相应的中断处理程序（运行在内核态）在内存中的存放位置。

系统调用

系统调用是操作系统提供给应用程序使用的接口，应用程序可以通过系统调用来请求获得操作系统内核的服务。
系统调用是应用程序取得操作系统所有服务的唯一途径。
程序结构由一组系统调用组成。系统调用=程序接口=广义指令。
每一个系统调用都是一个能完成特定功能的子程序。

系统调用和库函数的区别

库函数属于用户程序而非系统调用，是系统调用的上层。
库函数：高级语言中提供的与系统调用对应的函数，目的是隐藏访管指令的细节，使得系统调用更为方便抽象。
普通应用程序：可直接进行系统调用，也可使用库函数。
高级编程语言：向上提供库函数或把系统调用封装为库函数。
操作系统：向上提供系统调用。

系统调用是必须的

用户通过系统调用请求资源，由操作系统内核进行统一管理分配，避免资源使用冲突。
用户程序运行在用户态，不能直接访问内核数据或执行特权指令。通过系统调用进入内核态后，操作系统接管控制权，在内核态重可以直接访问系统资源，保证了系统的稳定性和安全性。

系统调用按功能分类

凡是与共享资源有关的操作（存储分配、I/O 操作、文件管理等），都必须通过系统调用的方式向操作系统内核提出服务请求，由操作系统内核代为完成。
设备管理：完成设备的请求/释放/启动等功能。
文件管理：完成文件的读写/创建/删除等功能。
进程控制：完成进程的创建/撤销/阻塞/唤醒等功能。
进程通信：完成进程之间的消息传递/信号传递等功能。
内存管理：完成内存的分配/回收等功能。

系统调用的过程

①传递系统调用参数：在用户态下，通过若干传参指令将若干个参数分别传入寄存器中，操作系统根据参数提供对应的系统调用服务。
②执行陷入指令并切换至内核态：陷入指令引发中断，CPU 硬件自动完成从用户态到内核态的特权级转换。。硬件与内核协同保存现场，将 PC、PSW 及通用寄存器内容压入内核堆栈。
③定位并执行相应服务程序：执行中断服务程序的过程中，根据寄存器中的参数执行对应的系统调用处理程序。此过程对用户是透明的。
④恢复现场并返回用户态：操作系统完成服务后将结果放入约定的寄存器或内存中。操作系统返回指令，CPU 状态从内核态切回用户态，并从内核栈恢复先前保存的上下文。用户程序从系统调用指令之后的位置继续执行，并自行获取返回值。

系统调用和一般过程调用的主要区别

  1. 运行状态不同。普通过程调用的调用者与被调用者运行在同一特权级；而系统调用的调用者运行在用户态，被调用者运行在内核态。
  2. 状态转换不同。普通过程调用无须特权级切换，可以直接跳转；系统调用则需要通过陷入指令 (Trap) 触发，先从用户态切换到内核态，再由内核分派至相应处理程序。
  3. 返回机制不同。系统调用执行完毕后，内核可能根据调度策略决定是否切换进程；而普通过程调用总是直接返回原调用点。
  4. 嵌套调用限制不同。系统调用的嵌套深度受到内核栈空间的限制；而普通过程调用的嵌套深度通常仅受用户栈大小约束。

子程序调用

系统调用是用户程序调用系统程序，子程序调用时用户程序调用用户程序。
过程调用和函数调用都是子程序调用。

子程序调用和中断处理的区别

子程序调用只需要保护程序断点，即该指令的下一条指令的地址；中断处理不仅要保护断点（PC 的内容），还要保护程序状态字寄存器的内容 PSW。
子程序调用是通过调用指令（CALL）引起，是事先安排的；中断的产生是随机的。
子程序受主程序或上层子程序控制；中断服务程序一般与被中断的现行程序无关。
不 i 存在同一时刻调用多个子程序的情况；有可能发生多个外设同时请求 CPU 服务的情况。
无论中断处理还是子程序调用都需要保存通用数据寄存器和通用地址寄存器中的内容。在中断处理过程中程序计数器（PC）和程序状态字（PSW）寄存器的内容可由软件来实现。
程序状态字（PSW）寄存器用于记录当前处理器的状态和控制指令的执行顺序，并且保留与运行程序相关的各种信息，主要作用是实现程序状态的保护和恢复。子程序调用在进程内部执行，不会涉及特权模式的切换，通常由硬件自动保存程序计数器（PC），而 PSW 的保存可视情况由软件处理。

操作系统的结构

分层

将操作系统分为若干层次，每个层次由若干模块组成。最底层为硬件系统（裸机系统），最高层为用户接口（系统调用接口），每层只能调用紧邻它的低层的功能和服务，且不能跨层调用。

优点

① 便于调试与验证，系统可自底向上逐层开发与测试。层 1 完成且验证无误后，即可开发层 2, 因其仅依赖已验证的下层；后续各层以此类推。若某层出现错误，可将其定位在该层内部，因其所有依赖的下层均已通过验证。
②易于扩充与维护。在保持层间接口不变的前提下，可独立修改、替换或新增某一层的实现，而不会影响其他层次的功能。

缺点

①层次划分困难。合理界定各层的功能边界较为复杂，且一旦依赖关系固化，系统架构可能缺乏灵活性。
② 运行效率较低。执行一个高层功能 通常需穿越多个中间层，每层之间的参数传递与控制转移会引入额外开销，从而影响系统整体性能。

模块化

模块化是将操作系统按功能划分为若干具有一定独立性的模块。还可进一步将模块细分为若干子模块，并且规定子模块之间的接口。这种设计方法称为模块-接口法。
在划分模块时：
若模块过小，虽然可降低单个模块的复杂性，但会导致模块间交互频繁， 增加系统的整体复杂度；
若模块过大，则模块内部结构复杂，难以维护。
衡量模块独立性的主要标准有两个：
内聚性：模块内部各组成部分间联系的紧密程度。内聚性越高，模块独立性越好。
耦合度：模块间相互依赖和影响的程度。耦合度越低，模块独立性越好。

优点

①提高了操作系统设计的正确性、可理解性和可维护性。
②增强了系统 的可适应性，便于功能扩展，支持动态加载新的内核模块，添加新模块功能无需对整个内核进行重新编译。
③支持并行开发，加速操作系统研制进程。
④任何模块都可以直接调用其他模块，无需采用消息传递进行通信。效率高。

缺点

①难以准确预估和定义模块间的接口规范，可能导致设计完成后难以满足实际要求。
②各模块并行开发，若缺乏清晰的依赖关系定义，可能导致开发或集成的无序性。
③只适用于系统规模小、模块数量少、使用环境比较稳定的系统。

宏内核

将系统的主要功能模块集成在一个紧密耦合的整体中，运行于内核态，从而为用户程序提供高效的系统服务。
优点：高性能。内核内部各功能可以直接相互调用。
缺点：内核代码庞大，结构混乱，难以维护；某个功能出错可能导致整个系统崩溃。

微内核

基本概念：

足够小的内核 内核只保留最基本功能：a.与硬件处理最紧密相关的部分；b.基本的抽象机制； c.客户与服务器之间通信。
仅含有时钟管理、中断管理、进程通信、原语等与硬件关联紧密的模块。
进程管理（部分）、文件管理、设备管理等功能在用户态以用户进程的形式运行。
基于客户/服务器模块 OS 绝大部分在微内核外的服务器中实现。
客户端与服务器借助微内核提供消息传递机制进行消息交互。
机制与策略分离 机制：实现某一功能具体执行的机构。
策略：在机制的基础上借助某些参数和算法来实现该功能的优化。
机制处于系统基层，策略处于系统高层。在微内核 OS 中，通常将机制放在 OS 的微内核中。
基本功能：
进程（线程）管理 进程（线程）间通信功能是微内核 OS 最基本的功能，频繁使用，通信功能放入微内核中。
微内核 OS 在进程管理上，核心理念是遵循“机制与策略分离”的原则，将功能明确划分为内核内部的核心“机制”和内核外部的具体“策略”。即进程管理的部分功能在微内核内，部分在微内核外。
微内核内（机制）：微内核仅包含最基础的核心机制，如进程间通信、进程切换、线程调度（仅限底层操作，如状态管理、上下文切换），以及多处理机之间的同步等功能。它专注于实现“如何”执行进程管理的基本操作。
微内核外（策略）：微内核外部的用户态服务器则负责具体的进程管理“策略”。这包括决定进程的初始化优先级、根据运行时需求动态调整优先级（如老化、IO 或 CPU 消耗调整），以及选择哪个进程应被执行。他侧重解决了“什么”进程应该被调度和“何时”调度的问题，并通过进程间通信机制调用微内核提供的底层机制来执行其策略。
低级存储器管理 微内核仅配置最基本的低级存储器管理机制，如页表机制和地址变换机制，这些机制用于将用户空间的逻辑地址转换为物理地址，这一部分依赖硬件。因此放入微内核。
而实现虚拟存储器管理的策略，包括应采用何种页面置换算法，采用何种内存分配与回收策略等，则应放在微内核外的存储器管理服务器中。
中断和陷入处理 微内核捕获所发生的中断和陷入事件，进行初步的处理，然后将有关事件的信息转换成消息后，把它发送给相关服务器。
服务器根据中断或陷入的类型调用相应的从处理程序来进行后期处理。
优点：
①扩展性和灵活性。新增或修改功能只需调整相应服务器，无须改动内核。
②可靠性和安全性。用户态服务的故障不会导致系统崩溃，且攻击面更小。
③可移植性。仅微内核包含硬件相关代码，其余服务器与平台无关，便于移植。
④分布式计算。客户/服务器间通过消息传递通信，易于扩展至网络环境。
缺点：
用户态下的各功能模块不可以直接相互调用，只能通过内核的“消息传递”来间接通信。需要频繁地在核心态和用户态之间交换，开销大，性能低。

外核

外核的基本理念是：内核不再提供传统操作系统中的进程、虚拟内存等抽象事物，而是极小化其自身，仅专注于对底层物理资源进行隔离和安全复用。具体的硬件资源管理职责，则完全下放给应用程序自行实现。
应用程序可以通过系统提供的库函数调用普通内核中的功能，也可以通过库函数直接调用外核所提供的各个功能。
将物理资源直接暴露给用户级系统，自身仅负责资源的安全分配与隔离。
在这种操作系统中，操作系统=内核+外核；
内核：负责进程调度、进程通信等功能以及与硬件资源无关的功能。
外核：负责为用户进程分配未经抽象的硬件资源（如磁盘的存储空间、内存的存储空间），且由外核负责保护资源的使用安全。
优点：
①减少抽象开销。传统操作系统强制引入虚拟内存、虚拟文件系统等映射层，而外核允许 用户级系统按需定制资源使用方式，显著降低了系统开销。
②提升灵活性与性能。用户级系统可根据应用特性优化资源管理策略 (如数据库可以直接 管理磁盘块), 充分发挥硬件的潜力。
③清晰分离保护与实现。外核仅负责资源保护，功能实现完全置于用户空间，系统结构简 洁且易于验证。
缺点：
①降低了系统的一致性。
②使系统变得更复杂。

操作系统引导

基本输入输出系统（BIOS）是固化到计算机主板上的一个只读存储器芯片内的一组程序，保存计算机最重要的基本输入输出程序、开机后自检程序和系统自启动程序。BIOS 被存储在主板上的 ROM 芯片里，开机后计算机会自动将其加载到内存中执行。

操作系统引导是指计算机利用 CPU 运行特定程序，通过程序识别硬盘分区及其上的操作系统，最后通过程序启动操作系统的过程。

常见操作系统的引导过程：

①加电与指令跳转：
计算机加电后，CPU 进行复位操作。此时 CPU 的 CS（代码段）寄存器和 IP（指令指针）寄存器会被强制初始化指向一个预设的物理内存地址（通常为 FFFF0H）。该地址处通常存放着一条 JMP 跳转指令，CPU 执行该指令后，将控制流跳转到 BIOS（或者 UEFI）固件程序的入口地址，开始执行固件代码。
②硬件自检（POST）：
BIOS 程序执行上电自检，检测 CPU、内存、显卡、键盘等关键硬件设备。

  • 若硬件状态正常，继续执行后续流程。
  • 若发现硬件故障，主板通常会通过蜂鸣器发出报警声。

③系统初始化
硬件检测通过后，BIOS 将存储在 CMOS 芯片中的参数配置应用到各个硬件设备中。随后，BIOS 会在内存的低地址区域建立中断向量表，并登记各种硬件中断服务程序（如硬盘读写、键盘输入等）的入口地址。
④加载主引导记录（MBR）：
BIOS 按照用户设置的启动顺序逐一扫描存储介质。BIOS 读取存储介质起始位置（主引导区）的数据，并检查该扇区的最后两个字节。

  • 若最后两个字节为 0x55aa，则确认该介质存在有效的主引导记录（MBR）。
  • BIOS 将检测到的 MBR 读取并加载到内存地址 0x7c00 处。
  • BIOS 将 CPU 的控制权移交给位于 0x7c00 处的主引导程序。

⑤扫描分区表与定位活动分区：
MBR 程序开始执行，其主要任务是扫描 MBR 内部的硬盘分区表（DPT）。它会在分区表中寻找标记为“活动”的主分区，并识别该分区的分区引导记录。
⑥加载分区引导记录（PBR/VBR）：
MBR 根据分区表信息，找到活动分区的第一个扇区，即分区引导记录（PBR 或 VBR）。MBR 将 PBR 读取到内存中并执行。PBR 的主要职责是定位并启动存储在该分区目录下的启动管理程序。
⑦内核加载：
启动管理程序接管控制权后，负责将操作系统内核的初始部分从磁盘加载到物理内存（RAM）中。

  • 内核完成内存管理、进程管理、设备驱动等系统级的初始化工作。
  • 初始化完成后，内核开始运行用户空间的第一个进程，至此，整个计算机系统正式运行起来，准备接受用户操作。
    引导并不要求一次性加载完整 OS，其余部分可以按需加载。

知识点

引导块

存储介质（如硬盘、闪存等）的第一个扇区。引导块在硬盘上通常就是指 MBR。
引导加载程序定位： 引导块包含引导加载程序的信息，它指示计算机的固件在哪里可以找到更复杂的引导加载程序。该引导加载程序是启动过程的下一步，负责加载操作系统的核心代码。
引导加载程序初始化： 引导块中的代码负责初始化引导加载程序的执行环境，例如设置必要的寄存器和内存区域，以确保引导加载程序能够正确执行。
引导加载程序的跳转： 引导块中的代码通常包含一条跳转指令，将控制权移交到引导加载程序代码所在的扇区。此后，引导加载程序将继续执行引导过程，加载操作系统的核心代码。

扫描分区表

引导程序通过扫描存储器介质上的分区表来找到活动分区或用户指定的分区。

分区表

一种数据结构，它记录了存储介质上每个分区的大小、起始地址和类型。在多操作系统环境中，分区表尤其关键，因为它包含了不同操作系统所在位置的相关信息，引导程序据此来识别和启动相应的操作系统。

安装有操作系统的分区被标记为活动分区，并使用其启动操作系统，如 C 盘。
计算机主存由 RAM 和 ROM 组成，BIOS（基本输入/输出系统）或 UEFI 固件固化在主板上的 ROM 芯片内。其中，最重要的是 ROM 引导程序（自举程序）。
RAM（随机存取存储器）在关机或断电后数据会丢失，而 ROM（只读存储器）的数据则能持久保存。根据这一特性，可以令计算机在开机时固定地从 ROM 的某一区域中启动自举程序，ROM 引导程序的作用是指示 CPU 将磁盘的主引导记录（MBR）读入内存。

精简流程：BIOS→MBR→PBR→启动管理器→内核。
计算机开机后，操作系统及其程序最终被加载到 RAM（内存系统区）中进行。BIOS/UEFI 固件存在于 ROM 中，而运行中的操作系统位于 RAM 中。

虚拟机

虚拟机是一台逻辑计算机，是利用特殊的虚拟化技术，通过隐藏计算平台的物理特性，为用户提供抽象、统一、模拟的计算环境，虚拟化需要利用虚拟机管理程序，该管理程序通常称为虚拟机监视器（VMM）。虚拟机管理程序是一个软件程序，它提供抽象层，处理物理和虚拟资源之间的转换，并管理虚拟机（VM）的创建和支持。
虚拟机管理程序运行的物理硬件通常称为主机，管理程序创建和支持的 VM 通常称为客户机。
目前主流的虚拟化方案分为两类。

第一类虚拟机管理程序（裸金属架构）

直接运行在裸机上，是唯一一个运行在最高特权级的程序，向上层提供若干台虚拟机，这些虚拟机是裸机硬件的精确复制品。
在此类架构中，客户操作系统运行于虚拟内核态，它认为自己处于真实的 CPU 内核态，但实际上并非如此；其用户进程则运行在真实的用户态。当客户操作系统执行一条仅允许在真实 内核态下执行的敏感指令时，会触发异常并陷入虚拟机管理程序。
在支持硬件虚拟化的 CPU 上，虚拟机管理程序能够根据执行上下文判断该指令源自客户操作系统还是用户程序：若为前者，则代为完成其功能；若为后者 (用户程序非法执行敏感指令), 则模拟真实硬件的异常响应行为。而在早期不支持硬件虚拟化的 CPU 上，所有敏感指令均 被透明重定向到虚拟机管理程序，由其通过软件模拟实现相应功能。

第二类虚拟机管理程序（寄居架构）

以应用程序的形式运行在宿主操作系统 (如 Windows 或 Linux) 之上，依赖宿主系统进行资源分配与调度，本质上是一个用户态进程。这种虚拟机管理程序仍然伪装成具有 CPU 和各种设备的完整计算机。底层操作系统的存在会引入不可避免的延迟，因为所有该管理程序的活动和每个 VM 的工作都必须通过主机操作系统。第二类 VMM 内的虚拟机可以打包为镜像文件，实现跨主机迁移这使其特别适合开发、测试和跨平台环境中快速部署 。

运行在两类虚拟机管理程序上的操作系统都称为客户操作系统，对于第二类虚拟机管理程序，运行在底层硬件上的操作系统都称为宿主操作系统。
